## 0. Grounding (what this plan relies on, with sources)

| Fact | Source |
| :-- | :-- |
| A v3 kit is a directory `<stem>/` with `<stem>.yaml` (first line `# syntax=docker/sandbox-kit:3`) and optional `<stem>.dockerfile`; `kind` is `workload`, `mixin` or `set`. Mixins are overlays: their image layers are applied onto the workload, their `USER/ENTRYPOINT/CMD/WORKDIR` are ignored, additive `ENV` merges. | [SPEC-v3](https://github.com/docker/sandbox-kit-spec/blob/main/docs/spec/SPEC-v3.md) §5, §10 |
| `args:` entries carry `default`/`required`, `enum`/`pattern`, `buildArg` (passed as `--build-arg`), `env` (exported into the container at create). There is no top-level `env`. `${{ kit.args.x }}` expands in hook commands and file contents. | SPEC-v3 "Args" |
| `com.docker.sandbox/lifecycle@1`: `install[]` (once at create, default user root), `startup[]` (every boot, default uid 1000, `background`), `files[]` (`path`, `content`, `mode`, `overwrite`). Hooks see only the env names they declare in `env:` plus PATH/HOME/HOSTNAME/TERM/PWD. `command` is a string (`sh -c`) or argv list. | `docs/spec/capabilities/com.docker.sandbox/lifecycle@1.md` (copy in scratchpad `upstream/`) |
| `com.docker.sandbox/credential@1`: `service`, `phase`, `apiKey{name, proxyManaged, inject[]}`, `oauth{tokenEndpoint, resourceHosts, sentinels, credentialFile{path, structure, format}}`. One owner per (service, phase) in a composition. `optional: true` entries are skipped when no host secret is bound. The runtime sets `SBX_CRED_<SERVICE>_MODE` (`none`, `apikey`, `oauth`) and hooks must declare it in `env:` to read it. | `credential@1.md`; Docker's `claude-mixin` descriptor |
| `com.docker.sandbox/volume@1`: `path`, `size`, `tmpfs`, `mode`. Block volumes survive stop/start, recreate and (since sbx 0.50, same sandbox name) removal. | `volume@1.md`; sbx 0.50.0 notes |
| `com.docker.sandbox/network-policy@1`: `install.allow/deny`, `runtime.allow/deny`; inject domains must be in the allow list. `agent-context@1`: `content` or `contentFile`. `sbx@1`: config-less, workload only; image config must declare `user`. | capability docs |
| Docker's v3 `shell` workload (`docker.io/sbx/shell`, image `docker.io/sbx/shell-image`) is Debian 13 DHI with bash, git, curl, gh, jq, make, python3.14, pip, uv, sudo, docker engine. It declares **no credentials** and no network policy. | `docker buildx imagetools inspect docker.io/sbx/shell:latest` (descriptor annotation) |
| Docker publishes v3 agent mixins: `docker.io/sbx/claude-mixin`, `codex-mixin`, `opencode-mixin`, `antigravity-mixin`, `pi-mixin`. Each ships the binary as an overlay and its own optional credential. A kit image may be used in `FROM`; its capabilities do **not** carry over, only files. | Docker Hub; `base-images` docs |
| `docker.io/sbx/shell-credentials` is a declaration-only mixin with eight optional credentials. It is the sanctioned way to add proxy credentials to an agentless sandbox. | Hub page; `upstream/shell-credentials.yaml` |
| sbx 0.51: `shell` resolves to the v3 kit; v1/v2 kits cannot compose with v3; `sbx kit add` installs image content in all-v3 sandboxes while preserving filesystem changes; `kit add` accepts startup hooks since 0.48. | release notes 0.48.0, 0.51.0 |
| sbx 0.48 CLI changes: `ls`, `template ls`, `rm`, `stop`, `template rm` `--json` return arrays (`.[]` not `.sandboxes[]`), snake_case fields, errors on stderr, piped confirmations rejected. | release notes 0.48.0 |
| Local v3 source kits are built by sbx when the sandbox is created. On 0.46 the build runs in a shared builder sandbox `sbx-kit-builder` with its own engine (`sbx kit builder --help`); `sbx kit validate` of a v3 source dir needs that builder. `docker buildx build -f <stem>.yaml <dir>` validates a descriptor on the host (verified here on both a probe mixin and a probe workload). | local CLI help; learn guide |
| `sbx run`/`create` positional may be a local kit directory (`./dir`), ZIP, git or OCI reference. `--kit` takes mixins; `--kit-arg kit.name=value` scopes an argument to one kit. | `sbx run --help` |

Unverified until sbx is updated (see §11): that the builder sandbox builds our workload without host Docker; that `sbx template save` + `sbx create --template` still works for a v3 composition; the descriptor file-name convention sbx expects when given a directory (`<dirname>.yaml` is assumed); that `${{ kit.args.x }}` expands inside `network-policy@1` allow entries (chrome-host) and inside `credentialFile.structure` values (agy-credentials), which the spec only promises for hook commands and `files[].content`; whether a named, non-proxyManaged `GH_TOKEN` is populated in local sandboxes (the opencode Copilot seed depends on it).

## 1. Target architecture

Data flow for `up`:

```
agy.yaml ──load──> AgyConfig ──workload.write──> ~/.agy-sandbox/kits/<sandbox>/workload/
                                 │                      (workload.yaml + workload.dockerfile)
                                 └──compose.plan──> SandboxPlan ──sandbox.create──> sbx create ... <workload-dir> <workspace>
                                                        │
                                                        └──compose.save_plan──> ~/.agy-sandbox/sandboxes/<sandbox>/plan.json
```

Dependency rules (enforced by review, see §9):

- `errors`, `console`, `constants`, `paths` import nothing from the package (`paths` imports `constants`).
  `paths.state_dir()` honours `AGY_SANDBOX_STATE_DIR` so tests never write to `~/.agy-sandbox` (appendix A).
- `config` → `agents`, `constants`, `errors`.
- `kits` → `agents`, `constants`, `errors` (pure: reads descriptors, never runs sbx).
- `workload` → `config`, `constants`, `errors` (pure: writes files).
- `compose` → `config`, `kits`, `workload`, `constants` (pure).
- `sandbox` → `constants`, `errors`, `console`. **Only module that executes `sbx`.**
- `engine`, `upgrade` → everything above plus `guardian`, `host_browser`. Orchestration only.
- `cli` → `engine`, `upgrade`, `config`, `errors`, `console`, `spec_inspector`, `prompts`, `agents`, `cli_helpers`, `guardian`, `kits`, `workload`.
- `upgrade` → `engine` (desired_plan, host_browser_for, report_missing_secrets); `sandbox` imports `compose.SandboxPlan` and `kits.KitRef` for typing only.
- `print()` is allowed only in `console.py` and `cli.py`.

### 2.8 `compose.py` (new)

```python
@dataclass(frozen=True)
class SandboxPlan:
    name: str; workspace: str; clone: bool
    workload: str                     # workload dir
    mixins: tuple[KitRef, ...]        # ordered
    kit_args: tuple[str, ...]         # "kit.arg=value"
    env: tuple[str, ...]; ports: tuple[str, ...]
    auth_mode: str; agy_version: str
def plan(config: AgyConfig, *, workspace: str, workload: Path) -> SandboxPlan
def save_plan(plan: SandboxPlan) -> None        # ~/.agy-sandbox/sandboxes/<name>/plan.json
def load_plan(name: str) -> SandboxPlan | None
def delete_plan(name: str) -> None
```

Ordering rule in `plan()`: primary agent kit, then `config.kits` in order (deduplicated), then for proxy-managed one `<kit>-credentials` after each bundled kit that has one, then `chrome-host` when `host_browser.enabled`. sbx allows one owner per credential (service, phase), so two agents whose credential kits declare the same service (claude and opencode both own `anthropic`) are refused with a `ConfigError` before sbx is called. `kit_args` = `config.kit_args` as `key=value` plus `chrome-host.host_port=<host_browser.port>` (which replaces any `chrome-host.host_port` in `kit_args`). `env` = `config.env` unchanged. There is no auth-mode kit argument and no placeholder blanking. `Drift`, `diff` and `kit_args_for_kit` also live here (appendix C).

Case table for `upgrade`:

| Change in agy.yaml | Handled by |
| :-- | :-- |
| kit added (agent or mixin) | `upgrade` via `sbx kit add` |
| env, ports, host browser on | `upgrade` (env on attach, `sbx ports`, `kit add chrome-host`) |

## 3. Bundled kits (all v3, `kits/<name>/<name>.yaml` [+ `<name>.dockerfile`])

## 7. Error handling, end to end

- Library modules raise `AgyError` subclasses with a remedy in `hint`; they never print errors, never call `sys.exit`, never swallow `subprocess` failures silently.
- `sandbox.py` converts every non-zero exit into `SandboxError(command, returncode, stderr_tail)` and every missing binary/daemon/login into `SandboxUnavailable`.
- `upgrade` never partially applies: it computes `Drift` first and refuses before touching the sandbox when anything is not in-place. `recreate` keeps today's guarantee: snapshot before destroy, restore command printed on failure.
- `cli.main` is the single place that renders errors and chooses exit codes.

## 8. Output

All progress and warnings go through `console`. Messages name the exact next command when the user must act (`sbx login`, `sbx secret set <svc> --sandbox <name>`, `agy-sandbox recreate`).
